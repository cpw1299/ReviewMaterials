# 实现说明：与原设计文档的偏差及依据

本文记录实际实现相对 `doc/` 下 4 份原设计文档（开发任务文档、开发文档、设计文档、复习资料文档处理方法文档）的偏离点。**每一条都有对 4 份 DOCX 原文的实测数据支撑**，避免后人按已过时的文档返工。

## 1. 技术路线：uni-app x，而非 Vue 3 + Vite SPA

原文档假设 Vue 3 + TypeScript + Vite、`src/` 目录布局、`npm run dev:h5`。

实测：本仓库是 **uni-app x 工程**（`.uvue` 页面、UTS 语言、根级 `pages.json`/`manifest.json`、`App.uvue`），没有 package.json 构建脚本；npm 上的 `@dcloudio/uni-app-x` 只是类型包，不是编译器，编译链在 HBuilderX 内部。`src/` 子目录方案在根级工程结构下不可行。

**决策**：清空全部 demo 页面后沿用 uni-app x 工程路线（用户确认）。

## 2. 砍掉练习模块，只做阅读器

原设计文档规划了题目列表、答题、答案解析、错题/题目收藏。

实测 4 份 DOCX 全文：`答案` **0** 次、`解析` **0** 次、`选项` 标记 **0** 次——资料是纯知识点文本，不存在题库。

**决策**：不做练习（用户确认）。收藏对象相应从「题目」改为「小节」。

## 3. 不实现图片渲染

原设计文档要求支持资料内图片点击放大。

实测 4 份 DOCX 的 `word/media/` 均为 **0 张图**。

**决策**：数据 schema 不含 image 类型，阅读器不实现图片路径。

## 4. 无 Python 管线，结构化数据作为静态资源直接入库

原文档规划 `convert_docx.py` + `validate_materials.py` 常驻管线。

实测内容体量（命名空间感知统计）：

| 资料 | 非空段落 | 表格 | 字数 |
|---|---|---|---|
| 机械制图基础（本） | 473 | 5 | 5,257 |
| 计算机辅助产品设计 | 675 | 31 | 11,567 |
| 工业设计史 | 395 | 0 | 10,390 |
| 产品设计程序与方法 | 183 | 0 | 5,891 |

合计约 3.3 万字，一次性静态导入即可，无需按章节拆包或运行时转换。

**决策**（用户确认）：提取脚本只作为一次性工具（不在仓库交付物内），产物是 `common/materials/` 下 5 个 JSON，经 `loader.uts` 静态导入编译进包——运行期零 I/O，断网可用是结构性质。取而代之的常驻校验是 `scripts/check.py`（纯静态一致性检查，不需要 HBuilderX）。

## 5. 提取阶段实测到的关键事实（未来重建数据时必读）

- **章节号不在正文里**。`第一章`/`【1.1】` 等前缀来自 `numbering.xml` 的 `lvlText` 自动编号（`第%1章` + chineseCounting、`%1.%2` 等）。不还原就会丢失章节号。`numId="0"` 表示编号被显式取消，不能加前缀。
- **样式 id 是数字**，必须经 `styles.xml` 的 `w:name` 映射（本语料 `2`=heading1、`3`=heading2），不能假设 `Heading1`。
- **Word 的标题层级不可盲信**：工业设计史、产品设计程序与方法存在跳级（无 heading3）；产品设计程序与方法第 1 章是 heading1、第 2~5 章却是 heading2；机械制图附录口诀被标成 heading1。规范化时按实际嵌套关系重建了层级。
- **阅读单元必须按内容判定**，不能按 level：机械制图「附录二」是无子节点的 level 1；另三份资料每章 level 1 各挂一段【考情分析】/【核心逻辑】导语。按 level==2 过滤会漏掉这 54 段内容（loader.uts `isReadable`）。
- 数据保真验证：按位置 1:1 重建原文（空白归一化后逐段比对）4 份全部通过，无内容丢失；表格行列数与原文一致。

## 6. 验证边界

- **已静态自证**（`python scripts/check.py` 全部通过）：JSON 可解析、block 统一形状、`blockIds`/`parentId` 引用闭合、每 block 恰好归属一个 section、表格行宽一致、`index.json` 计数与实际一致、`pages.json` ↔ 页面文件 ↔ tabBar ↔ `theme.json` 一致、manifest 无 DCloud demo 凭据残留、全仓无指向已删路径的引用、样式符合暗黑模式规范（单类选择器、颜色走 `var(--x, 亮色fallback)`）。
- **必须由 HBuilderX 编译验证**（本机无法自证）：UTS 类型在 Kotlin/JS 目标下的编译、`import x from './x.json'` 深层嵌套对象的 `as` 转型、页面运行时表现。首次编译建议同时跑 Web 目标（类型错误暴露更直接）与 Android 基座。

## 7. 组件取舍

计划中的 `material-card`、`section-tree` 各只有一个使用方，直接内联在 index / detail 页内，未单独建组件；`content-block`、`progress-bar`、`empty-state` 因多页面复用而保留为 easycom 组件。
